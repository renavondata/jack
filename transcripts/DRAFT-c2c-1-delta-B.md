## Amendment 3 (18 November, counsel-5; the verbs that end on `main` follow a moved `main` — before the opening, one clause, a deliverable)

**Why.** Six verbs end by pushing `main`: `key`, `decision`, `amend`, `push`, and the master key's `forecast` and `resolve` (every caller of `main_ending`, `tools/jack` lines 118, 244, 282, 296, 299). Each is refused at its start unless local `main` equals the remote's: "Main verbs require HEAD to equal `origin/main`" (`RUNBOOK.md` line 38; `tools/jack` line 47). Each is refused at its end if `main` moved while it worked: "a push that is not a fast-forward is a refusal, never a retry with force" (`RUNBOOK.md` lines 42–43), and `push()` gives one refusal for every failure of `git push`, whatever its cause (`tools/jack` lines 27–29). The herald merges every few minutes. So the sovereign's pastes were built to wait for a quiet minute, and at C2a-prime's opening one waited about forty-two minutes of his sitting (COUNSEL-OPEN row 68: "because `jack decision` and `jack push` cannot follow a moved `main`"). The record of that day: "Agreed with him the same day: the verbs merge a moved `main` and retry, every check repeated, as a deliverable of C2c-1 with a pin".

**The clause.** The code is the builder's, in `tools/jack`, written to `RUNBOOK.md`'s text for it; that text is counsel's and reaches `main` first, by counsel's proposal, after the sovereign has read this brief ("Text before code", `RUNBOOK.md` lines 183–189). The clause binds the six verbs named above and no other. `merge` is outside it: it signs on the proposal's branch and "has no undo" (`RUNBOOK.md` lines 48–50). A party's branch verbs are outside it.

1. *At the start.* After the fetch, and after the refusals of a tree that is not clean and of a detached `HEAD`, and before the log is read: if `HEAD` equals `origin/main` the verb goes on; if `HEAD` is an ancestor of `origin/main` the verb fast-forwards local `main` to it (`git merge --ff-only`) and goes on; otherwise it refuses, since local `main` then holds a commit the remote lacks. The log's state, the signer's party and key, and everything else the verb reads are read after that, from the tree it then stands on. Today the log is folded and the key identified before the comparison (`tools/jack` lines 35–39, then line 47), so the order changes as well as the refusal.

2. *An attempt.* One attempt is the verb from its first precondition to its push of `main`. Its **base** is the commit `origin/main` named at the attempt's fetch. An attempt fetches once, at its start, so within an attempt `origin/main` means its base. Every check it makes, every file it reads from its arguments, the instant it signs, the entry it appends and the commit it makes are made on that base. The entry's `parent` is the hash of the last line of the base's log, as SPEC §3 has it, and is not a commit's hash.

3. *After a push of `main` that fails.* The verb does not conclude from the failure that nothing was pushed. Before it undoes anything it fetches again and compares:
   - (a) the attempt's commit is `origin/main` or an ancestor of it: the push landed. The verb undoes nothing, fast-forwards local `main` to `origin/main`, and ends as a success, printing that the remote accepted a push it had reported as failed;
   - (b) otherwise, `origin/main` is no longer the attempt's base: `main` moved. The verb undoes its effects as it does today (`git reset --hard origin/main`, and its own files under `transcripts/` removed; `tools/jack` lines 79–81) and makes a new attempt (point 4);
   - (c) otherwise the push failed with `main` where it was. The verb undoes its effects and refuses as today, printing what `git push` printed. It does not try again;
   - (d) the second fetch itself fails: the verb undoes its effects locally and refuses, saying that it could not read the remote and so does not know whether the entry landed, and that the remote's log is to be read before the verb is run again.

   A failure before the push — in the verb's own refusals, its effect, the kernel's refusal of the entry, the commit or `judge/selfcheck.py` — is a refusal as today and never a new attempt. No push is forced, and no attempt pushes anything but a fast-forward of `main`.

4. *A new attempt.* The verb starts again as a new process with the arguments it was given, so that the code it runs and every module it loads are those of the tree it now stands on, and nothing computed, read or signed in an earlier attempt is in memory. The earlier attempt's entry and signature are on no branch. Two things pass to the new process, as arguments and never through the environment (`RUNBOOK.md` line 36): the number of the attempt, and for `push` the commit BRANCH named at the first attempt. Each verb's own preconditions are therefore tested again on the new base: `decision promote` fetches the runs for the new `HEAD` and runs the status tool again at a new instant; `amend` tests again that the amendment is transmuted and not yet entered, appends its text to the charter as the new base has it, and computes a default `activate_at` from the new log's length, while an `activate_at` given by hand that the longer log has overtaken is refused by the kernel and ends the verb; `key`, `forecast` and `resolve` are refused wherever the new log refuses them.

5. *The bound.* A verb makes at most five attempts, the first included; `push`, whose every attempt runs the check and may run the differential, at most three. These are two constants of `RUNBOOK.md`'s text, held in `tools/jack` beside its other constants; they are not numbers of a window file, because these verbs run before any window opens and between windows, and `tools/jack` may not open a window file (R1). When the last attempt ends in case (b), the verb undoes its effects, leaves local `main` equal to `origin/main`, and refuses, naming the number: `main moved during each of N attempts`.

6. *`push BRANCH`.* Today the verb refuses "BRANCH not containing `origin/main`" (`RUNBOOK.md` line 110; `tools/jack` line 226), makes its checks in a worktree of BRANCH (line 235), and fast-forwards `main` to BRANCH, "never a merge commit, never a rebase" (`RUNBOOK.md` line 120; `tools/jack` line 239). Under this clause:
   - (a) *BRANCH is a commit.* At the first attempt the verb resolves BRANCH once to a commit, and everything after speaks of that commit and never of the name again. A later attempt refuses if BRANCH no longer names it. The verb never commits to BRANCH and never moves its ref.
   - (b) *The candidate.* If BRANCH's commit contains the base, the candidate is BRANCH's commit, as today. If it does not, the candidate is one merge commit that the verb makes in a temporary worktree. Its first parent is the base and its second BRANCH's commit, so that `main`'s first-parent history stays `main`'s. It is authored and committed under the pusher's git identity, and its message is `Merge main into BRANCH (jack push)` with the pusher's own filled `Proposer:` trailer. Its tree is chosen path by path. Call the single merge base of the two commits the *ancestor*; a path's *value* at a commit is its mode and blob, or its absence. Where BRANCH's value equals the ancestor's, the candidate takes `main`'s value (the base's); where `main`'s value equals the ancestor's, or the two values are equal, it takes BRANCH's; where both differ from the ancestor's and from each other, the push is refused, naming the path. No file's content is merged. `log.jsonl` is a path like any other: a BRANCH whose log differs from the ancestor's is refused once `main`'s log has grown. The push is also refused where the two commits have more than one merge base, where a path's value on either side is a gitlink (mode 160000), and where the chosen values would make one path both a file and a directory.
   - (c) *Every check is of the candidate.* The scan for filled trailers runs over the commits the candidate has and the base lacks. The digest comparison, the check, the test of whether a run of record is required, and that run are made on the candidate; the run's twelve parts each report `commit` equal to the candidate's commit, where today they report "BRANCH's head" (`RUNBOOK.md` lines 116–117). The read gate is given the candidate.
   - (d) *The read gate sees what is pushed.* The gate today takes the brief, the reviews and the bytes each review vouches for from `origin/main` (`tools/jack` line 187, `current = tree_bytes(repo, "origin/main", brief)`; `RUNBOOK.md` lines 128–133), and of the branch it compares `judge/scope.json` alone (line 180). So a branch that changes the brief is admitted today on a read of the brief that `main` holds. This clause adds one test, whether or not `main` has moved. When `--opens LAYER` is required, the candidate's bytes at `transcripts/BRIEF-LAYER-draft.md`, at `transcripts/windows/LAYER.json` where `origin/main` holds that file, and at each review the gate counts, must equal `origin/main`'s; if any differs the push is refused, naming the path. What was read is then what is pushed.
   - (e) *The evidence files.* The review and the run's parts are written under `transcripts/` after the checks, as today (`tools/jack` lines 237–241). They are not part of the tree that was checked, and the self-check runs with them in place. This clause adds one refusal, made before the checks: a name the verb would write — `transcripts/` followed by the basename of `--review`, or a part's name — that already exists in the candidate's tree.
   - (f) *The effect.* Local `main`, which stands on the base, is fast-forwarded to the candidate, and the entry `push` is made on it as today. On any failure `main` returns to `origin/main` and BRANCH is untouched; a merge commit the verb made is then on no branch.

7. *The window.* Nothing in this clause permits a push that a window's rules refuse. R11 stands ("No verb fast-forwards a proposal onto `main` inside the window (`push` is refused there)") and so does criterion 3: a new attempt is not a second opening. Before `push` makes a new attempt it reads the entries that `origin/main`'s log now holds beyond the old base's, and if one of them is a `push` it refuses and makes no new attempt. A merge commit made under point 6 is the pusher's commit. What it changes against its first parent is a push's change and never a proposal's, whatever trailers BRANCH's commits carry: R11 knows a proposal's merge by its `merge` entry and its shape, and counts a push's commit as nobody's (`evidence_provenance`, twin 7).

**What it does not change.** No check is skipped, and none is remembered from an earlier attempt. An entry is lawful only on the prefix it finally lands on, and the kernel, the self-check and the judge decide that as they do today. No push is forced; no remote branch is deleted; no commit is rewritten. The verb merges no proposal and closes none. `merge` and every branch verb are as they were. BRANCH's ref never moves. A paste of the sovereign's needs no guard that waits for a quiet minute, and a guard still in a paste does no harm.

**What it does not establish.** That a push inside a window is lawful: point 7. That the files written under `transcripts/` after the checks were themselves checked: point 6 (e) keeps today's order and says so. That a moved `main` is a good `main`: the verb follows whatever the judge admitted. And case (d) of point 3 leaves one state the verb cannot decide — a push that failed while the remote could not be read — which it reports and does not guess at.

**The text owed first.** `RUNBOOK.md` is counsel's. After the sovereign's read of this brief and before the build, counsel proposes the text that replaces these sentences, each to say what the clause above says: line 38, "Main verbs require HEAD to equal `origin/main`"; lines 42–43, "a push that is not a fast-forward is a refusal, never a retry with force"; lines 44–47, the main verbs' order and "Whatever fails before the push leaves `main` equal to `origin/main` with nothing of the verb's left in the tree and nothing pushed"; line 110, "BRANCH not containing `origin/main`"; lines 116–117, "each reporting `commit` equal to BRANCH's head"; line 120, "never a merge commit, never a rebase"; lines 128–133, the gate's tests "on `origin/main`", to which point 6 (d)'s test is added. The two numbers of point 5 are stated there.

**What it costs.** An estimate, not a measurement: the change to `tools/jack` (339 lines on `main`) is some tens of lines, and the pin's fixtures, which need a remote that moves between a signature and a push, are several times that. Tests and pins count toward the window's cap. The cap is the sovereign's number, and this amendment is one of the things it must hold.

**Pin `verb_follows_main`.** The window file's criterion 4 (`pins_killed`) names it in `args.pins`, the sixteenth pin there. Each twin runs the verb against a fixture with its own bare remote, and a hook or a second clone moves that remote's `main` at a stated point. "Moved" means a new commit on the remote's `main` that appends one valid entry to the log.
- (1) `decision grant`; `main` moved once, after the entry is signed and before the push → two attempts; exactly one `decision` entry on the remote's `main`, on the moved head; its `parent` is the hash of the log line before it; the first attempt's signature is in no reachable commit.
- (2) `decision grant`; the remote refuses the push by a hook, `main` unmoved → one attempt; refusal carrying git's message; local `main` equals the remote's; no entry.
- (3) `decision grant`; the remote accepts the push and the client is made to report failure → one attempt; success; exactly one entry; local `main` equals the remote's.
- (4) `decision grant`; `main` moved after every signature → refusal after exactly five attempts, naming five; no entry of the verb's on the remote; local `main` equals the remote's.
- (5) `push BRANCH`; `main` moved after every check → refusal after exactly three attempts, naming three; no entry of the verb's on the remote; local `main` equals the remote's; BRANCH's ref is unmoved.
- (6) `decision grant`; the second fetch of point 3 fails → refusal saying the remote could not be read; no new attempt.
- (7) local `main` one commit behind the remote's → fast-forwarded, the verb goes on, and the entry's `parent` is of the remote's log; local `main` one commit ahead → refusal at the start, nothing signed.
- (8) `decision promote`; the commit that arrives makes the status tool print a criterion `unmet` → refusal on the second attempt; nothing pushed.
- (9) `amend` with no `--activate-at`; `main` moved once → the entry's `activate_at` is one more than the number of lines of the log it is appended to, the moved log; with an `--activate-at` that no longer exceeds the entry's `seq` on the moved log → refusal on the second attempt, by the kernel, and no third attempt.
- (10) `push BRANCH`; BRANCH does not contain `main`, and the two changed different paths → the candidate is one merge commit, first parent the remote's `main`, second BRANCH's commit; its tree has `main`'s value at the paths `main` changed and BRANCH's at the paths BRANCH changed; the run's parts name the candidate; `main` is fast-forwarded to it; BRANCH's ref is unmoved.
- (11) `push BRANCH`; both changed one path to different values → refusal naming the path; no merge commit on any branch. The same where the path is `log.jsonl`.
- (12) `push BRANCH --opens L`; BRANCH changes `transcripts/BRIEF-L-draft.md` and `main` holds an accepted review of `main`'s bytes → refusal naming the brief's path. This twin fails on `main`'s code today.
- (13) `push BRANCH --review F`; a file with F's basename is already under `transcripts/` in the candidate → refusal before the check runs.
- (14) `push BRANCH`; BRANCH's ref is moved between the first attempt and the second → refusal on the second attempt.
- (15) `push BRANCH`; the commit that arrives between attempts is itself a `push` → refusal, and no second attempt (point 7).
- (16) the commit that arrives changes `tools/jack` so that it prints a marker → the second attempt prints the marker: the code of the new tree ran.

Mutants: a new attempt on any failure of the push (2); the remote not fetched again before the cases are told apart (3, 6); the first signature or entry reused (1); a bound one too many or one too few, or the first attempt not counted (4, 5); a diverged local `main` rebased or reset (7); the status tool's first result reused (8); `activate_at` kept from the first attempt (9); the merge commit's parents in the other order, or a textual merge accepted (10, 11); the gate left reading `main`'s brief alone (12); an existing evidence file overwritten (13); BRANCH resolved again by name (14); a second `push` admitted (15); the verb looping in one process (16).
