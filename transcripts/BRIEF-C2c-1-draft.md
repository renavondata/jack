## 0. The law of this window is a file, and what binds the file

`transcripts/windows/C2c-1.json` is this window: its opening rule and preconditions, its promotion forecast, its end, its budget rule, its numbers and the constants SPEC fixes, its processes, what is frozen, its criteria with the evidence each reads, its reads, and what is reserved to the sovereign. `tools/status.py` reads the window it assesses from `transcripts/windows/<subject>.json` **when that file exists**. The windows closed before C2c-1 — C1a, C1b, C2a, C2a-prime, C2b — have no file and get none: they are assessed by the code that closed them, as history, and their reports stand (v3 promised files for them; the third read showed the promise cannot be kept — their promotion forecasts carry no hash to bind a file to, and C1a's criteria have no kind — so it is withdrawn, not softened). From C2c-1 on, a window is its file. This prose is commentary: where it and the file differ, the file governs and the difference is a finding.

**Binding.** The trusted-base digest does not cover `transcripts/` (SPEC §10.1) and `transcripts/windows/` is in counsel's own scope, so the file is bound outside counsel's reach, in this order at the opening sitting: the file is final and read; the sovereign enters `decision budget "C2c-1: window file sha256:<hash>; …"` (the hash is his act); counsel enters the promotion forecast naming the same hash; the opening push carries the file. `status.py`, **before it reads any criterion**, hashes the file at the assessed prefix and compares it with the hash in the latest `decision budget` on the prefix whose subject begins `C2c-1:` and with the promotion forecast's `args.window_sha256`; a mismatch refuses the whole assessment (`promote C2c-1: refused: window file changed`). That check lives in code (R9), not in the file, so an in-window edit of the file cannot remove it; and `frozen` names the file, so an in-window edit is also criterion 3's failure. No cycle: the file cites no seq; the budget rule finds the entry; and the file is final at its proposal — every hash it names is of a file that exists then (`world-types.json`), the undertakings inventory is a commit of `main`'s history, not a file, and what the builder writes afterwards is bound by `frozen` at the opening tree, not by a hash the file would have to know in advance.

### R1 Numerals are housed

Everything that reads a window file lives in one module, `tools/window.py` (the builder's): the opening rule, the binding (R9), the kinds (R2), the processes (R10), the writ and ratio lines the file governs. `tools/status.py` keeps the code that closed the earlier windows and dispatches a subject with a file to `window.py`; it is history and R1 does not scan it. R1 scans `tools/window.py` and `tools/value.py` whole: no integer, fraction or float literal outside `{0, 1, −1}`; no string literal that parses as a number or as an instant in §4's `ts` form; except a string that is exactly a key of the window file's `numbers`, `spec_constants` or `history`, used as a lookup into that table. `numbers` holds integers, booleans or integer pairs (a pair is a fraction, numerator first); `spec_constants` the constants the record fixes with the text that fixes each; `history` the closed windows' constants that `value.py` still needs (`c1b_last_seq`, 337), with the text each comes from. A criterion's `args` are of five shapes, declared by its kind: numeric (`counted`, `kernel`, `threshold`, `null`, `grace`, `lead`, `min_rows`, `max` — each a `numbers` key), boolean (`scope_equals_spec`), a path or path prefix (`map`, `shells`, `inventory`, `due_file`), a name or list of names the kind interprets (`shows`, `process`, `proposer`, `type`, `pins`, `rows`, `sources`), or a reference to another top-level member of the file (`frozen`, `inventory` → `undertakings`, `witnesses` → `ratchet`). A process's `null` and `threshold` are numeric. Dates and seqs of windows are found by `opens` and `end`, never written.

**Pin `numerals_housed`.** Twins: (1) `tools/window.py` and `tools/value.py` as proposed pass the scan; (2) every numeric `args` of every criterion, and the `null` and `threshold` of every process, of every window file on `main` resolves to a `numbers` key holding an integer or a pair; (3) `tools/window.py` is the only file under `tools/` that opens a path under `transcripts/windows/` (a scan for the string). Mutants: `P0 = Fraction(6, 11)` in `window.py` (twin 1); `6900` (twin 1); `int("6900")` (twin 1); `"2026-11-17T12:00:00Z"` (twin 1); `20.0` (twin 1); `math.log(999)` written inline instead of through the table (twin 1); `337` inline in `value.py` (twin 1); a criterion whose numeric `args` names a missing key (twin 2); a process whose `null` names a missing key (twin 2); the file read from `status.py`, where a literal escapes the scan (twin 3).

### R2 Criteria are a closed set of kinds, each three-valued

A criterion is `{id, kind, args, evidence?, text}`; `evidence` is a list; `kind` is one of `verified_run`, `tree_bounds`, `pins_killed`, `eprocess`, `no_claim_past_due_unescalated`, `ratchet`, `count_zero`, `undertakings_kept`, `no_veto`, `ratio` (ten). A kind outside the set refuses the whole assessment. Each prints one of three values in this order (M.2): `unmet` when the inputs supplied already show failure; `unknown (no <evidence>)` when an `evidence` it names is absent, or `unknown (stale <evidence>)` when the file's `evidence` entry gives a staleness rule and the newest file fails it; else `met` or `unmet`. The line printed is `criterion <id>: <text> <value>`.

**Pin `criteria_three_valued`** (on `count_zero`, which reads the acts evidence for its first source and the log for its second — the on-log repairs as `tools/status.py`'s item loop defines them: entries signed by a genesis key of type `forecast`, `resolution`, `merge` or `spec_conflict`, and decisions of kind `fix`; his other decisions and his `key`, `amend`, `push` and `proposal` entries are not repairs — and on `pins_killed`, which reads the run and the tree).
