# FIX-20261123-check: run the proposal's check side by side and clean up after it, and make one promotion test hermetic

Counsel's text, 23 November 2026, for the sovereign's read (CHARTER A2.10). The builder makes it under `transcripts/sessions/fix.md`, on branch `FIX-20261123-check`, and proposes it. It changes when `tools/jack`'s check runs its three commands and where they keep their temporary files. It does not change what the commands are or what the check refuses. It also adds two arguments to one test's `git merge`.

**Why.**
- **Every proposal runs the check before it is made.** `tools/jack proposal` runs `the_check` (`tools/jack` line 98) on the session's machine. That is the three commands of `CHECK` (line 13), one after another: the unit tests, the pins and the kernel count. It does this for every proposal, a stream's forecasts or a resolution included (ADVISER.md entry 150).
- **Since the push of seq 7281, that check takes about 26 minutes on steel,** and the court's hourly work waits on it. The unit tests and the pins are independent processes, and each reads the tree without writing to it: after a full run of each, `git status --porcelain --ignored` lists nothing but `__pycache__` (counsel's check, 23 November). Run side by side, the check should take about as long as the longer of the two, plus whatever they lose by sharing the machine.
- **The check's commands leave their temporary files behind, and `/tmp` on steel fills.**
  - On 23 November at about 06:27Z a resolver's check failed. 7 of 311 unit tests errored, and the one its report shows was a `git init` in a new directory under `/tmp` that exited 128 (runner #1249). The session did not propose its six resolutions.
  - About ten minutes later `/tmp`, a 16G memory disk, held 12G in 75,242 entries, with 72% of its inodes used (the sovereign's paste, ADVISER.md entry 165).
  - Before each session the runner sweeps some of these leftovers, those older than an hour. It misses four kinds the code makes: `sim-`, `pins-`, `diff-keys-` and `promotion-replay-`.
  - Two suites at once would fill `/tmp` faster. So the check gives its commands a temporary directory of their own and removes it when they end.
- **One test still depends on the machine's git identity.** In `tests/test_promotion_judge.py`, the `git merge -q --no-ff` at line 151 of `test_every_entry_commit_including_a_bad_side_branch_is_judged` passes no identity. The same file's line 172 does. That test broke `main`'s `tests` job on 22 November (FIX-20261122). The workflow now supplies an identity, but a session's machine may not.

**The change.**
1. **`the_check(cwd)` runs the kernel count first, then the unit tests and the pins side by side, and waits for both.**
   - Each command is its own process, run with `sys.executable` from `cwd`, as today.
   - The count goes first and alone because it reads every file under `kernel/`. In `tools/jack push` the check runs in a fresh worktree, where the other two would be writing `kernel/__pycache__` at that moment. The count takes under a second.
   - Whatever the count returns, the other two still run.
   - Capture each command's standard output and standard error separately, so that no pipe can fill and block it, for example to temporary files.
2. **The three commands share one temporary directory, which the check makes and removes.** `the_check` makes it with `tempfile.TemporaryDirectory` and runs each command with `TMPDIR` set to it in the command's environment. Nothing else in the environment changes. When the check returns or refuses, the directory and everything under it are gone.
3. **It refuses exactly as today.**
   - If any command fails, it refuses for the first failing command in `CHECK`'s order: the unit tests, then the pins, then the count.
   - The message is today's, character for character: `the check fails: `, that command's arguments after `sys.executable` joined by spaces, a newline, and then `(stdout + stderr)[-1500:]`. That is the command's standard output and standard error joined in that order, and then the last 1500 characters of the whole.
   - If none fails, it returns as today.
   - It waits for both of the side-by-side commands to end before it refuses or returns, and leaves no process running.
4. **The merge at line 151 of `tests/test_promotion_judge.py` passes `-c user.name=t -c user.email=t@t`,** as line 172 does.
5. **One test is added:** `test_check_names_the_first_failure_in_its_order`, in `tests/test_jack.py`. In the fixture that file already builds, it makes four cases, with stand-ins of its own for the fixture's unit test, pins and count where a case needs them.
   - **The unit tests and the pins both fail.** `tools/jack proposal` refuses, and the reason begins `the check fails: -m unittest`.
   - **The pins and the count both fail,** and the pins print 2,000 characters to standard output and 10 to standard error. The verb refuses, and the reason begins `the check fails: pins/run.py`. After that first line it is exactly the last 1,500 characters of the two outputs joined, standard output first.
   - **The count alone fails.** The verb refuses, and the reason begins `the check fails: tools/count_kernel.py`.
   - **Nothing fails.** The unit test and the pins each take at least a second, and each of the three commands records when it started, when it ended and the `TMPDIR` it saw, in a directory the test names to them through the environment. Afterwards:
     - the count ended before either of the other two started;
     - the unit test and the pins overlapped: each started before the other ended;
     - all three saw the same `TMPDIR`, which is not the test's own temporary directory and no longer exists.
6. **Nothing else.**
   - `CHECK`'s commands are unchanged.
   - No other verb or function of `tools/jack` changes.
   - No test's assertions change.

**Paths.**
- **May change:** `tools/jack`, `tests/test_jack.py` (point 5 only), `tests/test_promotion_judge.py` (point 4 only).
- **May not change:** any other file.

**Size.** `main` has 8,245 counted lines against a cap of 8,400, and `tools/` and `tests/` are counted. This change adds at most 80 counted lines.
