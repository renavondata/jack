# SPEC patch for C2c-2 (draft v3, counsel-3, 7 November 2026, after one read — runner issue #376, 16 findings — and a pre-read) — one kind, one ground

This is the text a builder's branch for C2c-2 begins with (RUNBOOK §`jack push`: "a change to SPEC.md that needs code is the first commit of the builder's branch — counsel's patch, applied and read by Guy there"). It binds nothing until that push. It is deliberately smaller than `transcripts/RESEARCH-self-similarity-20261105.md` §3.3 proposed: the texts on `main` are already named by entries — every `merge` carries the commit it merged and every `push` the digest it authorised, so what `main` holds at any prefix is a function of the log — and the two things that are not are a direction of the sovereign's made in a chat, and a read that a convention requires and nothing checks. The patch adds one `decision` kind for the first and one judge ground for the second. `enact` as a unification of `push` and `amend` is not needed for the bootstrap and waits for a case.

## 1. `wish`: the sovereign's directions and rulings as entries

**SPEC §5, the `decision` row.** `kind`: one of `veto promote budget grant transmute fix wish`. For `wish`, `subject` matches `^transcripts/[A-Za-z0-9][A-Za-z0-9._/-]*@sha256:[0-9a-f]{64}$` — a path under `transcripts/` and the SHA-256 of a file's bytes. The kernel checks the shape and nothing else: whether such a file exists is not in `log.jsonl` (§1) and is the clerk's question. No required member is added to any type; the row widens one member's set and constrains one subject's shape, so every earlier valid log replays unchanged (§5's own rule: no earlier `decision` has kind `wish`).

**SPEC §7.** No new state. The kernel records a `wish` like any `decision`.

**What a wish is (SPEC §10, informative; the clerk).** A `wish` is the sovereign's signature over a text: his direction or ruling, which until now lived in a chat and a quotation, becomes an entry — counted by the acts evidence as a decision and not a repair, dated by the log, and named by hash so that nobody can later say he directed something else. It is an act, not an executable rule: the clerk evaluates no prose. The decidable part is presence: `tools/clerk.py` prints `W6 wish <seq>: <path>@sha256:<hex> — <commit> | absent` where `<commit>` is the first commit on `main`'s first-parent history at which the path has those bytes, or `absent` when none does; a later change to the file does not unbind the wish, because the bytes it names stay in history. A brief that cites a direction cites its wish; a direction with no wish is a quotation. `transcripts/CASES.md`'s "Rulings are not entries on the log" ends at the first `wish`; its index stays as the reading aid. The wishes entered in C2c-2's opening sitting, each by the hash of the file as it stands on `main` that day — two: `transcripts/RULING-20261104-window-fix.md` (the ruling of 4 November with its corrections) and `transcripts/COUNSEL-OPEN.md` (whose rows 33, 37, 39, 42, 43 and 44 quote the decision of 4 November and the direction, stop, choice and settlement of 5–7 November; rows 35, 36, 40 and 42 his read instants; and a row before the sitting the C2c-1 read of that brief's §2). Two files, two wishes; v1 said five and v2 four, counting before listing. C2c-2's window file lists the two paths, and its criterion is that a wish naming each is on the log with `W6` printing a commit.

**Kernel2.** `isDecisionKind` gains `wish`; the subject shape is checked by the same regular expression, written out in `checker.go` as the Python kernel writes it. Two checkers, one regex, one vector each way.

**Vectors** (the reviewer's proposal after the push, since they pass only against the new kernel): `spec/vectors/logs/<n>_wish_ok.jsonl` (a `wish` by the master key with a well-formed subject, admitted), `<n>_wish_bad_kind.jsonl` (`kind: wisj`, schema), `<n>_wish_bad_subject.jsonl` (a `wish` whose subject lacks the hash, schema). The differential's simulator kind `wish` (`sim/gen.py`; the builder's proposal after the push, with `tests/test_sim.py`'s `KINDS` slice).

## 2. `unread_text`: the read a text that claims force must carry

**SPEC §10, a fifteenth ground (the judge, not the kernel).**

15. **unread_text** — the proposal changes a path the `read` list of `judge/scope.json` covers, and no review on `main` qualifies for it. A path is covered when a `read` entry matches it: an entry ending in `/` matches the directory, one ending in `*` matches every path beginning with the part before the `*` (the `read` list alone admits `*`; `paths`, `parties` and `counted` keep §10's rule), otherwise exactly that file. A review qualifies when it is a file `transcripts/REVIEW-*.md` on `main` at the judgment, brought there by a `proposal` entry whose commit adds it and whose `proposer` differs from this proposal's `proposer`; begins `VERDICT: ACCEPT` or `VERDICT: ACCEPT WITH OBLIGATIONS`; its `Reviewed tree:` names a commit C the repository holds (any branch, any pull request — the judge fetches it by hash; reachability from the head is not required, because the court re-proposes by cherry-pick and a review of the bytes is a review of the bytes) such that for every covered path changed between the proposal's merge base with `main` and its head — added, modified or deleted — the bytes at C equal the bytes at the head, a path absent at both counting as equal; and its `Reader:` line's model — the token after `model ` up to the next `;` in the line `Reader: <party> <key_id>; model <model id>; <date>`, the form the record's reviews already use — differs from the `Model:` trailer of the drafter's commit, which is the newest commit after the merge base that is not a merge commit and changes a covered path (not SPEC §10.7's content commit, which is a merge commit whenever the branch merged `main`, as the verb itself advises; the merge carries no model). A covered change whose drafter's commit carries no `Model:` trailer is refused on this ground: a drafter that does not say what it is cannot be read by something else. At C2c-2 the `read` list is `transcripts/sessions/`, `transcripts/windows/`, `transcripts/runner/`, `tools/runner/`, `transcripts/BRIEF-*`, `transcripts/RULING-*`, `transcripts/CASES.md`, `transcripts/COUNSEL-OPEN.md`, `LAW.md`, `RUNBOOK.md` — the texts that claim force or index it (COUNSEL-OPEN row 34's list: a judgment, the index, `LAW.md`, a brief). `COUNSEL-OPEN.md` is on it because the clerk gives its rows force today (a row naming `W3 merge <seq>` discharges that writ, `tools/clerk.py`); the cost is a read per batch of rows, which is counsel's and is the point. Pin `text_unread`: a proposal changing a session template with no qualifying review is refused; its twin, the same with the review on `main` by another proposer, is admitted; mutants: the `Reviewed tree` test dropped; a reviewed commit before the merge base accepted; a deletion not counted as a change; a review added on the proposal's own branch accepted; the reader's model equal to the drafter's accepted; a missing `Model:` trailer accepted.

**The same rule as the opening gate, moved.** `tools/jack push --opens` (#182) already requires, for a brief, a review on `main` brought by a proposal of another principal whose reviewed bytes equal the brief's. Ground 15 is that rule for every covered path and every proposal, in the judge, where a session cannot route around it; the verb keeps its check for the opening push (a `push` is not judged by ground 15, and the sovereign's push carries the brief the reviews name). The order of acts: the drafter pushes the draft branch and opens no pull request; a reader of another family reads it at a commit and proposes the review naming that commit (its path is not covered, so no review is needed for a review); the herald merges the review; the drafter then merges `main` and proposes — last, so that the review is on `main` before the proposal is judged and the proposal is not staled by the review's own merge. A review of other bytes than the head's does not qualify, by the bytes test, whatever its date.

**The `Model:` trailer.** A session's content commits carry `Model: <model id>` as a trailer, written by the session from the issue's `model:` header (the templates under `transcripts/sessions/` say so from C2c-2; today a session's content commit carries no trailer at all, `Proposer:` being written by the verbs on log commits only); counsel's hand commits carry it beside `Proposer:`. It is read by `git log -1 --format=%(trailers:key=Model,valueonly)` from the drafter's commit as defined above. It is a claim by the drafter about itself, checkable against the runner's issue and nothing in the tree; its use here is only that a reader must differ from it.

**Why the judge and not the kernel.** A read is a file in the tree and a line in it; the kernel reads bytes of `log.jsonl` only (§1). The ground reads two trees and the log, which is the judge's domain (§10 preamble), and nothing outside git and the log (A2.3).

## 4. What this patch does not do

It does not change `push`, `amend`, `transmute` or the charter's procedure (A2.7, SPEC §10.13). It does not add `claim` or `enact`. It does not make the sovereign the author of session templates: a template changes by a counsel proposal with a read on `main`, merged by the herald, as today — ground 15 only refuses the one without the read. It does not make the clerk read prose: a wish's force is read by people and cited by briefs; the clerk prints whether the bytes exist.
