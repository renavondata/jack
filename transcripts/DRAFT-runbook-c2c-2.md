### Added to `## jack decision KIND SUBJECT`

**`wish`** (C2c-2: `transcripts/SPEC-PATCH-c2c-2-draft.md` §1; in force from the merge of the proposal that gives the verb the kind, and refused by the verb before it). KIND may be `wish`. SUBJECT is then `<path>@sha256:<hex>`, in SPEC §5's shape: a path of the repository and the SHA-256 of bytes. The verb refuses, before it signs, a SUBJECT of another shape, and one whose path is not a file in `HEAD`'s tree with exactly those bytes (`wish: <path> has other bytes on main`, or `is not on main`): he signs for what `main` holds. Entry: `decision` {kind: `wish`, subject}. A wish gives no order and has no effect on the state. It is his signature naming bytes, and what the bytes say is read from the file: a ruling, a direction, or a text he has read. To name several texts in one entry he names a read list, a file under `transcripts/reads/` whose every line is `<path>@sha256:<hex>`; the verb checks each line of the list as it checks a SUBJECT.

### Added to `## jack clerk`

**`W6`, the wishes** (C2c-2: the same §1; from the merge of the proposal that implements it). For each `wish` on the log the clerk prints `W6 wish <seq>: <path>@sha256:<hex> — <commit>`, where `<commit>` is the first commit on `main`'s first-parent history at which the path has those bytes, or `— absent` when none has. For a read list it prints one further line for each pair in it, ending `via <seq>`, or the one line ending `malformed list`. A line whose bytes extend, as a proper prefix, the bytes an earlier wish names for the same path ends `extends <seq>`, with the latest such wish. `W6` lines are information: they open no writ and have no deadline.

### Added to `## jack push BRANCH --review FILE | --review none [--opens LAYER]`

**The push by keys** (C2c-2; in force from the merge of the proposal that implements it; until then the text above stands). The rule is `transcripts/SPEC-PATCH-c2c-2-draft.md` §3, whole, and where this paragraph and that section differ, that section governs. From then:

- `--review PATH` names a `transcripts/REVIEW-*.md` file that is already on `origin/main`, brought there by the proposal of the principal that holds `pins/`, with an accepting first line. `--review none` is refused. **The verb no longer copies a review into `transcripts/`** (the sentence above beginning "`--review FILE` is copied" and the words "and the review" in the effect no longer apply); the entry's `review` is the SHA-256 of the file on `origin/main`.
- The verb reads no trailer as a fact. It refuses unless every check of §3 holds, and names the first that fails: `review` (checks 1 and 2: the file, who brought it, its verdict, one `Reviewed tree:` that is an ancestor of BRANCH); `built` (check 3: a `BUILT` file on `origin/main` brought by the principal that holds `tests/`, naming the tree the reader read the builder's changes from); `own` (check 4: every pin and vector that differs from `main` signed for by path and hash in the review, and `main` unchanged there since the read); `head` (check 5: elsewhere the head holds the build's bytes or `main`'s and nothing else); `text` (check 6: each text the review names has `main`'s bytes and a wish naming them); `descent` (check 7: every commit `main` would receive descends from those wishes' commits); `covered` (check 8: no path on the `read` list differs from `main`).
- A branch is assembled as §3 says under "How a push is assembled": the builder's `BUILT` file and the reader's review are each proposed from a branch that holds that file alone, and `main` is merged into the code branch after both are on it. A second build or a second read is recorded in a new file: a file whose bytes on `main` differ from those its adding proposal brought satisfies no check.
- These checks come before the check of BRANCH's tree and the run of record, and change neither. The fast-forward is made to the commit the checks were run on, by its hash, and never to BRANCH's name; the verb's git commands after BRANCH's code has run are run with hooks off; and before the push the verb reads back the commit it made and refuses unless its one parent is the checked commit and its tree differs from that commit's only by what the verb itself placed. It pushes that commit by its hash.

With `--opens LAYER`, the read gate above still applies to the brief, and one of the review's `Text:` lines names that brief.
